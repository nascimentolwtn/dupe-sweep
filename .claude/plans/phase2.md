Phase 2+ roadmap (reference only — do not build any of this yet)

Context for future sessions. Not in scope now.

Metadata on thumbnails. Each item in a group card should show date/time (AssetEntity.createDateTime), dimensions (width/height), file size, and storage path (relativePath on Android). Directly fixes a documented complaint about the app that inspired this ("no info about what I'm about to delete").
WhatsApp media cleanup. WhatsApp images/videos show up as their own album ("WhatsApp Images", "WhatsApp Video") in the normal MediaStore/ photo_manager album listing, so this reuses the existing pipeline, just scoped to that album. One constraint to set expectations on now: there's no reliable way to break this down "by chat" from a third-party app — that metadata lives inside WhatsApp's own sandboxed database, not in the files themselves, and reading it needs root. Scope this as "WhatsApp Images/Videos, deduped," not "per-chat."
Blurry/low-quality photo detector. Reuses the sharpness scoring already planned for ranking duplicates, but run across the whole library instead of just within a burst. Don't hardcode an absolute blur threshold — it doesn't generalize across resolutions/content. Compute the score for everything and flag the bottom 5-10%, or just present a sorted list for the user to skim.
Cache/junk file cleaner. Setting expectations before this gets built: since Android 8, apps cannot clear another app's cache — that needs a signature-level permission normal apps don't get. What "junk cleaners" on the Play Store actually do is: clear their own cache (not useful to you), find leftover APK installers in Downloads (genuinely doable via a normal file scan), and show per-app storage via StorageStatsManager (needs the user to manually grant "Usage access") with a button that deep-links to Android's own App Info screen for the user to tap "Clear cache" themselves. Scope this feature that way, not as "automatically clean other apps' cache," which isn't technically possible on modern Android.
Large-file finder (independent of duplicates). Finding any file over N MB, any type, anywhere on the device needs raw filesystem access, which scoped storage blocks by default. Since this app is sideloaded and never goes through Play Store review, using MANAGE_EXTERNAL_STORAGE ("All files access") is the pragmatic choice — Play Store restricts that permission heavily for public listings, but that restriction doesn't apply to an app you install yourself via ADB. With it granted, a plain recursive directory walk with a size filter covers this.
